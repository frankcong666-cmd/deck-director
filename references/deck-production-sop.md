# Deck production SOP

## 1. Brief

Collect only the inputs that change the output:

- Audience and setting
- Desired outcome
- Topic, evidence, and non-negotiable facts
- Language, slide count, and presentation duration
- Format requirements and delivery deadline
- Any brand, template, references, or visual preferences

If a choice materially changes the deck, surface it early. Otherwise make a reasonable assumption and state it briefly.

## 2. Story architecture

Write a one-sentence point of view. Then give every slide a job: orient, frame a problem, establish evidence, explain a mechanism, compare options, make a recommendation, or close. Remove slides that repeat a job already done.

For a talk, draft the script alongside the outline. A useful pacing estimate is 115 to 130 English words per minute, leaving room for page turns and pauses. Adjust for the speaker's language and confidence.

## 3. Art direction

Choose a visual system after understanding the story. Define:

- Primary layout logic: full-bleed, editorial grid, typographic, evidence-led, diagrammatic, or another deliberate approach
- Type hierarchy and text density
- Color palette and contrast rules
- Image treatment: photography, product screenshots, illustration, generated concept art, archival material, or mixed media
- Pacing: where the deck should breathe, intensify, or slow down

Show visual directions as coherent mini-compositions. Different directions should change more than the color palette.

## 4. Asset plan

Assign the most credible visual form to each point. Use product screenshots or source material for proof. Use diagrams when relationships matter. Use generated visuals when they communicate an abstract mood or idea better than literal evidence.

Record source links in notes when the deck relies on external facts or images. Never imply that a generated asset documents a real product, person, place, or event.

## 5. Production

Build slides around one dominant idea. Make the reading order obvious through size, position, and contrast. Keep spacing intentional and use the same structural rules across related slides.

For editable PPTX output, preserve the user's template and the slide dimensions. Keep text, tables, charts, and essential diagrams editable when the request requires it.

## 6. Review loop

Render the deck and assess it at two levels:

- **Deck level:** narrative rhythm, visual consistency, variety, and pacing
- **Slide level:** hierarchy, text fit, contrast, alignment, crops, and unintentional overlaps

Respond to critique with a targeted pass. Do not replace an approved visual system unless the feedback challenges the system itself.

## 7. Delivery

Provide the requested deck and supporting assets. Include the script, speaker notes, or timing plan only when asked. Explain only limitations that affect the user's ability to use the deliverable.
